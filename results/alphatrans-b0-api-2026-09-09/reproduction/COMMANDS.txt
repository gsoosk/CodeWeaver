Re-scoring the frozen B0 API outputs
====================================

Use Linux with Python 3.12.3, pytest 9.1.1 and the AlphaTrans test dependencies.
Activate the benchmark environment if available:

  source "$HOME/cwenv/bin/activate"

Use the AlphaTrans dataset at commit c1cabf93d41a153de207d6b098e1da7bbd79abab.
The wrapper checks the dataset revision, oracle fixture manifest, bundled oracle
script hash and package manifest before running pytest.

From the CodeWeaver repository root:

  bash results/alphatrans-b0-api-2026-09-09/reproduction/score.sh commons-cli per-file "$HOME/AlphaTrans"
  bash results/alphatrans-b0-api-2026-09-09/reproduction/score.sh commons-csv per-file "$HOME/AlphaTrans"
  bash results/alphatrans-b0-api-2026-09-09/reproduction/score.sh commons-fileupload per-file "$HOME/AlphaTrans"
  bash results/alphatrans-b0-api-2026-09-09/reproduction/score.sh commons-validator per-file "$HOME/AlphaTrans"

Replace per-file with whole-repo-single-call for the secondary arm.

Every command returns nonzero: all retained outputs have failures, and
commons-csv (per-file and whole-repo) plus commons-validator (per-file) also
produce collection errors. Run the commands individually, not chained with &&.

commons-csv per-file does not import at all. Its counts are not a pass rate.
commons-validator per-file has 8 collection errors, so its counts are not a
clean full-suite rate on the 462 denominator used by the other arms.

The wrapper uses the bundled public oracle script in a fresh temporary subject
tree. No pipeline/skips.json is present, so no repair-budget deferrals apply.
The fixed golden-baseline exclusions are preserved: one CurrencyValidator test
for commons-validator. Suite self-skips are reported separately.

This reproduces scoring of frozen output, not generation. No API access, proxy,
or model calls are required, and none of the generation code is included here.

Recorded scoring environment: LANG=C.UTF-8; LC_ALL and TZ unset.
Generated Python bytes are unchanged. Machine paths in textual evidence are
normalized and original hashes are retained in
metadata/publication-provenance.json.
