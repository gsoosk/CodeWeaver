# AlphaTrans `commons-cli` — Java → Python, CodeWeaver run `alphatrans-cli-azure-001`

**Headline: the translation passes 380 of 381 hidden oracle tests — one test short of
AlphaTrans's own manually verified human translation, on a suite the agents never saw.**

| Configuration | Oracle tests passed | Exit |
|---|---|---|
| **CodeWeaver (this run)** | **380 / 381** | 1 |
| AlphaTrans golden (human-written, same harness) — *ceiling* | 381 / 381 | 0 |
| Unimplemented interface skeleton, same harness — *floor* | 1 / 381 | 1 |

All numbers are **independently recomputed** by staging the translation against the
pristine oracle (`data/oracle_scores.txt`), never read out of the pipeline's own
`report.json`. 56 tests are skipped by the suite itself in every configuration
(including the golden one) and are excluded from the denominator on both sides.

## Protocol: the oracle was held out

- The oracle is **AlphaTrans's manually verified Python test suite** — human-written,
  not self-translated, and never authored or edited by the agents.
- It is **never present in the working copy**. Each scored run verifies a SHA256
  manifest, stages `src/main` (working copy) + `src/test` (pristine master) into a
  throwaway tree, runs pytest, and deletes it.
- Post-run audit: **0 oracle test files** were found anywhere under the working copy,
  and the oracle manifest verified **INTACT**.
- Milestones and their test gates were derived **mechanically from the interface
  skeleton** (`Foo.py` → token `FooTest`), never by inspecting the oracle.

The agents' feedback signals were therefore: the Python interpreter (`build_check`),
their own self-authored tests, and the oracle's **pass/fail counts** — not its source.

## The one failure

`BugsTest::test11458` — `AssertionError: -D option not found`. A Java-properties-style
`-Dkey=value` parsing edge case. It is a genuine behavioral gap, not a harness artifact:
the golden translation passes it under the identical harness.

## Caveats — read before citing

1. **N = 1 project, 1 repetition.** No variance can be reported. The protocol in
   `PAPER_INSTRUCTIONS.md` §4.5 requires ≥3 repetitions; this is a single pilot run.
2. **Not a head-to-head with AlphaTrans's published numbers.** Their Table 2 reports
   *per-fragment* counts read from CodeQL-derived schema JSON; this is a
   *project-level test-pass rate*. The denominators differ and must not be pooled.
   The meaningful comparison here is against the **golden ceiling on the same harness**.
3. **Leakage risk is high and unaudited.** Apache Commons CLI is a famous, long-public
   codebase that is almost certainly in the model's training data. This result should
   not be read as evidence about unseen code until a leakage audit is done.
4. **The subject is a reduced project**, not upstream Commons CLI: third-party
   libraries stripped, overloaded methods renamed with numeric suffixes
   (`hasOption1`/`hasOption2`).
5. **Cost is not recorded.** The Copilot CLI transcripts in `data/transcripts/`
   contain no `premium_request` events, so no cost figure is available for this run.
6. **A prior interrupted run is not included here.** An earlier attempt on a
   workstation scored 183/379 with milestones M5–M11 skipped; it ran with a defective
   gate resolution (`pytest -k` substring matching pulled later milestones' tests into
   earlier gates) that was fixed before this run. It is mentioned for honesty, not
   offered as a comparison.
7. **No Burr UI trajectory.** The tracking extra was not installed at run time, so
   `tracker_enabled()` returned False and the run proceeded without telemetry
   (by design). The full trajectory is in `data/pipeline/burr.db`.
